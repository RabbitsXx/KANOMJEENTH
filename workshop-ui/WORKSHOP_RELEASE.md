# Kanomjeen Workshop UI Release Guide

## Release target
Publish one Steam Workshop item containing the Kanomjeen UI Effect used by the server plugin suite.

Default identity:
- Master bundle: `kanomjeen_ui.masterbundle`
- Asset prefix: `Assets/KanomjeenUI`
- Asset bundle version: `6`
- Effect ID: `51000`
- Effect GUID: `2f8df4942fe04a27a9636942abb3cd21`
- UI contract: `1.0`

## Prerequisites
- Installed current Unturned client with `Extras/Sources/Project.unitypackage` available.
- Unity version compatible with the current Unturned modding source package. `Asset_Bundle_Version 6` is the Unity 2022 LTS generation used by this package.
- Steam account allowed to publish Workshop content.

## 1. Prepare Unity
1. Create/open the modding Unity project.
2. Import `Unturned/Extras/Sources/Project.unitypackage` from the same game installation you are targeting.
3. Copy the repository folder:
   `UnityProject/Assets/KanomjeenUI`
   into the Unity project's `Assets/KanomjeenUI`.
4. Thai-capable UI needs **Kanit**, which this repository already ships in three weights under
   `Assets/KanomjeenUI/Fonts/` (`Kanit-Regular.ttf`, `Kanit-SemiBold.ttf`, `Kanit-Bold.ttf`) together
   with its SIL OFL 1.1 notice. If the files are missing or their git blob hashes do not match
   `Fonts/README.md`, re-download them from the upstream Google Fonts repository — do not substitute a
   font without redistribution rights.
5. Allow Unity to compile the Editor script. Resolve every compiler error before continuing.
6. Run **Kanomjeen → Export Workshop UI Master Bundle**. This rebuilds and validates the Effect prefab before packaging, so the export cannot accidentally reuse an old prefab layout.
7. Verify the generated prefab file:
   `Assets/KanomjeenUI/Effects/KanomjeenUI/Effect.prefab`.
8. Verify the generated master bundle files in `WorkshopExport`.
9. Check the Unity Console. A warning that the Kanit fonts are missing is acceptable only for an explicitly English-only staging test; it is a release blocker when Thai text is required. To prove the *bundle* carries them, dump it with `Kanomjeen → Inspect Bundle...` and confirm the `## Fonts` section lists Kanit-Regular, Kanit-SemiBold and Kanit-Bold with `dynamic=True`.

## 2. Validate prefab before export
Inspect the prefab hierarchy and confirm at minimum:
- `KJ_Root`
- `KJ_Close`
- `KJ_Screen_main`
- `KJ_Screen_waypoints`
- `KJ_Screen_tpa`
- `KJ_Screen_homes`
- `KJ_Screen_kits`
- `KJ_Screen_stats`
- `KJ_Screen_airdrop`
- `KJ_Screen_admin`

The Waypoints screen contains eight reusable rows named `KJ_Waypoint_Row_0` through `_7`, matching the Track/Delete callbacks in `UI_CONTRACT.md`.

Compare all interactive names against `UI_CONTRACT.md`.

## 3. Prepare Workshop content root
The package root should contain the metadata and generated master bundle outputs. A typical final layout is:

```text
Kanomjeen_UI_Workshop/
├── MasterBundle.dat
├── kanomjeen_ui.masterbundle
├── kanomjeen_ui.masterbundle.hash
├── kanomjeen_ui_linux.masterbundle
├── kanomjeen_ui_mac.masterbundle
└── Effects/
    └── KanomjeenUI/
        └── Asset.dat
```

Copy from this repository:
- `MasterBundle.dat`
- `Effects/KanomjeenUI/Asset.dat`

Do not invent or hand-create the binary bundle/hash files. They must be generated by the Unturned/Unity Master Bundle workflow.

## 4. Export master bundle
Use the Master Bundle Tool supplied through Unturned's current modding project package.

Preferred path: run **Kanomjeen → Export Workshop UI Master Bundle** from this repository's builder. It regenerates `Effect.prefab`, validates text layout pivots, assigns `kanomjeen_ui.masterbundle`, and then calls the Unturned master bundle export helper. Do not manually export a previously generated prefab unless you have just rebuilt and inspected it in the same Unity session.

Release requirements:
- bundle name matches `MasterBundle.dat`
- asset prefix is `Assets/KanomjeenUI`
- multiplatform export enabled for the intended public release
- generated `.hash` kept beside the bundle
- no missing prefab references

## 5. First local/client test
Before public Workshop upload:
1. Put the package where the local Unturned client can load test content according to the current modding workflow.
2. Launch a staging server with `Kanomjeen.Core` and set `UiEffectId` to `51000`.
3. Join with a test client that has the UI content installed.
4. Run `/menu`.
5. Test close/reopen, every main card and every feature callback.

If the Effect does not load, do not change the server code blindly. Verify:
- bundle loaded
- asset GUID/ID is unique
- `Asset.dat` points to the expected Effect prefab through the standard master bundle asset lookup
- bundle/prefix naming
- client actually has the Workshop/local mod

## 6. Upload Workshop item
Upload the validated package using Unturned's current Workshop publishing workflow.

After the first upload gives you a Workshop File ID:
- record the ID in the project/release notes
- configure `AssetBundleCustomData`/Owner Workshop File Id in the Unity project where supported by the current Unturned toolchain
- rebuild/reupload so the bundle is associated with the intended Workshop item

Do not put the Workshop File ID into server plugin code. The server should only need the Workshop item in its Workshop download list and the UI effect identity in Core config.

## 7. Server deployment
Add the Workshop item to the dedicated server's Workshop download/content configuration using your existing server management method.

Deploy plugin DLLs separately under Rocket/LDM. Workshop content and Rocket plugin DLLs solve different halves of the system:
- Workshop: client UI asset
- Rocket plugins: server authority/business logic

## Release checklist
- [ ] Unity Editor builder compiles
- [ ] Effect prefab generated
- [ ] UI contract names match exactly
- [ ] Effect ID `51000` is unique in your server content set
- [ ] Effect GUID is unique and frozen
- [ ] Windows bundle generated
- [ ] Linux/macOS bundles generated if required by the Master Bundle Tool/release workflow
- [ ] `.hash` generated and shipped
- [ ] `/menu` displays correctly
- [ ] modal cursor/focus clears on `KJ_Close`
- [ ] TPA accept/deny callbacks tested with two real clients
- [ ] Home rows tested after reconnect/restart
- [ ] Kit claim tested with full inventory
- [ ] Stats fields tested after kill/death/reconnect
- [ ] Airdrop ACTIVE/STANDBY states tested
- [ ] Staff button hidden for non-staff
- [ ] Staff buttons rejected server-side without permissions
- [ ] 16:9 / 16:10 / ultrawide visual pass
- [ ] Thai/English text pass
- [ ] Workshop Owner File ID configured after first upload where applicable

## Contract changes after release
Never silently reuse a published UI with renamed callback elements. For breaking UI changes:
1. bump `UiContractVersion`
2. update `UI_CONTRACT.md`
3. update Unity builder
4. update server plugins
5. stage both sides together
6. only then publish/deploy.
